# 決定 0038: 設定 UI の入口と、測っていない目盛りを見せないこと

決定 0013(設定アプリは WinUI 3)の残件。画面は4つとも実装されて実機で起動もして
いたが、**利用者がそこに到達できず、到達しても実際より細かい選択肢を見せていた。**

## 背景 — 足りなかったのは画面ではなかった

引き継ぎ書は「UI はまだ薄い」と書いていたが、読み直すと薄いのは画面ではなかった。
実物で確かめた4件:

1. **起動する手段が無い。** インストーラに `[Icons]` が無く、言語バーのメニューは
   空だった(`InitMenuImpl` は `return S_OK;` だけ)。設定アプリは `{app}` に入るので、
   `C:\Program Files\Ohagey` を自分で開いた人だけが使えた
2. **保存すると常駐設定が壊れる**(決定 0035 の追記に分けて書いた)
3. **反映の強さが 0〜150 の連続スライダ。** 実測があるのは3点だけ
4. **入っていないバックエンドが選べる。** 既定のインストーラは cpu しか入れない

## 決定1: 入口はスタートメニューを本線、言語バーは補助

`[Icons]` の1行が本線である。`#ifndef SkipSettingsApp` の内側に置いた —
CI は設定アプリを建てないので、**存在しない exe を指すショートカット**を作らせない。

言語バーのメニューにも「おはぎーの設定」を足した(`CLangBarItemButton::InitMenuImpl` /
`OnMenuSelectImpl`。SEH ラッパーは既にあったので、ホストアプリに新しい例外経路は
増えていない)。ただし**これが出るかどうかは Windows 次第**である:
この項目は `TF_LBI_STYLE_BTN_BUTTON` で、左クリックは あ↔A のトグルに使われている。
メニューを出すのに `TF_LBI_STYLE_BTN_MENU` が要るなら、同じ項目には両方を持たせられない。

**スタイルは変えなかった。** 変えると、実機で確認済みの「クリックで あ↔A」を
壊しうる。まず `InitMenu` を実装だけして実機で見る、という順にした。
出なければ本線(ショートカット)だけが残り、**この節は「効かなかった記録」になる。**

- **secure mode では出さない。** ログオン画面の裏で走っている IME が
  Program Files のアプリを起動する導線を持つ理由が無い
- **起動の失敗は黙って捨てる。** AppContainer では `CreateProcess` も
  `ShellExecuteEx` も拒否される(決定 0031)。他人のワープロの中から
  ダイアログを出すほうが害である。ログには1行だけ残す(エラーコードのみ)

## 決定2: 反映の強さは3択にする

スライダ(0〜150、1刻み)を **弱 50 / 標準 100 / 強 150** のラジオボタンにした。

理由は見た目ではない。**151段階あるという主張を、測定が支えていない。**
azooKey-Desktop が同じ変換器と同じ base で 0.5 / 1.0 / 1.5 を出しているのも同じ形である。

🔴 **「弱」の説明は、書いた当日に反証されて書き直した。**
最初は決定 0034 の当時の測定に従って「壊しませんが、学習した語も上がりません」と
書いた。同じ日に取り込みで alpha を掃引したところ、**50% でも材料が足りていれば
昇格する**(40行なら 2→1、10行なら 2→2)。**「効く」を「効かない」と表示していた**
ことになる。いまは「よく書く言い回しなら上がります。材料が少ないと上がりません」。
詳細は決定 0034 の 2026-08-28 追記。

⚠️ **この一件は3択という形そのものを弱めてはいない。** 掃引で分かったのは
「alpha × 材料の量」で決まるということで、**目盛りを細かくしても意味は増えない**
(利用者は材料の量を目盛りから知りようがない)。3点のままにしてある。

⚠️ **3択に無い値は書き換えない。** レジストリに 0 や 37 が入っていれば
「そのほか (37%)」として**表示だけ**し、利用者が3択を選ぶまで書かない。
まるめれば、**利用者が開いただけのページで設定が変わる**。それは決定 0035 が
存在して防いでいる壊れ方そのものである。スキーマの範囲(0〜150)も変えていない —
範囲は契約で、3択は UI の推奨にすぎない。

0 が生き残ることには意味がある: 順位に効かせないまま個人化はオンのまま、という
状態は選べるべきで、そこには**「控えは作られ続ける」**という既存の注意書きが要る。

## 決定3: 入っていないバックエンドは選ばせない

`backends\<name>\llama.dll` の実在を見る(`BackendAvailability`)。
無いものは選べなくし、**理由を項目名に書く**(「このインストーラーには
含まれていません」)。消さないのは、**利用者の疑問に答えるのは不在の説明**であって、
選択肢が1つしか無い画面ではないからである。

- 判定は **`llama.dll` 1つだけ**。エンジン側(`BackendLayout.swift`)と同じ規則にした。
  依存 DLL まで数えると llama.cpp のビルド構成の写しになり、必ず古くなる
- **cpu が無い場合だけ文言が違う。** cpu は無条件で同梱されるので、
  その不在は「パッケージ時の選択」ではなく**壊れたインストール**である
- 選択中のものが不在なら、既存の状態バーを Warning に上げる。
  「エンジンが要求どおり動いていないときだけ Warning」という既存の規則の延長

## 検証

- `dotnet test`(Core)**101件パス**
- TSF DLL: MSBuild x64 Release で通る
- 設定アプリ: VS の MSBuild(Professional 側)で Restore → Build。
  ⚠️ **Community 側の MSBuild では建たない** — `Microsoft.NET.Sdk` を解決できない。
  `docs/local-setup.md` の例が Professional を指しているのはこのため
- 実機: インストールして確認(下の「実機で見たこと」)

## 実機で見たこと(2026-08-28)

インストーラを作り直して**実際に入れた**(28.0 MB、`/SILENT /NOCLOSEAPPLICATIONS /NORESTART`、
終了コード 0)。3つの成果物とも `installed == built` を SHA-256 で確認している。

⚠️ **`/NOCLOSEAPPLICATIONS` は手で付けた。** `[Setup]` に `CloseApplications=no` が無く、
`ohagey.iss` の注釈が言う「利用者の Discord や LINE を閉じない」がスクリプトに
書かれていない(ロードマップに残してある)。

| 確認したこと | 結果 |
|---|---|
| スタートメニュー | `おはぎー 設定.lnk` が作られ、`OhageySettings.exe` を指す |
| 設定アプリの起動 | 起動して落ちない(`NumberBox` / `RadioButtons` を足した後も) |
| バックエンドの一覧 | **CPU だけ選択可**。CUDA / Vulkan は理由付きで選択不可 |
| 常駐スイッチ ON | 警告(ストアアプリ)+ 再起動の通知が出て、`IdleTimeoutSeconds=300` |
| 常駐スイッチ OFF | **`IdleTimeoutSeconds=0`**(直す前は、何を触っても 300 が書かれていた) |
| 反映の強さ | 3択。`標準`→100 / `弱`→50 を書く |
| 3択に無い値 | 37 を入れて開く → **「そのほか (37%)」が選択状態**。開いただけでは**書き換わらない** |
| 0 の扱い | 「そのほか (0%)」+ 既存の「0 では候補順に効きません」が出る |

確認は UI Automation で行った(スイッチとラジオを実際に操作し、レジストリを読み直している)。
検証で作った `HKCU\Software\Ohagey` は**消して元の「キー無し」に戻してある**。

### 言語バーのメニューは出た(利用者が実機で確認)

✅ **「おはぎーの設定」はタスクバーの IME アイコンから出る。** `tsf.log` が
13:28〜13:29 に**新しい DLL(283,648 bytes、13:10 ビルド)を5プロセスが読んだ**ことを
記録しており、その状態で確認されている。

**予想と違った。** この節はもともと「`TF_LBI_STYLE_BTN_BUTTON` にメニューは
来ないかもしれない」と書いてあった — 出すには `TF_LBI_STYLE_BTN_MENU` が要り、
それを足すと左クリックの あ↔A トグルを奪う、という想定である。
**実際には、スタイルを変えずに `InitMenu` が呼ばれる。** 左クリックはトグルのまま、
メニューは別に出る。

したがって**入口は2つある**:

| 入口 | 効くところ |
|---|---|
| スタートメニューのショートカット | いつでも |
| 言語バー(タスクバーの IME アイコン) | おはぎーが選択されているとき |

言語バー側のほうが「いま使っている IME の設定を開きたい」という動きに近いので、
**実際にはこちらが主に使われる**と思われる。スタートメニューは、
IME を選んでいないときにも辿れる唯一の道として残る。

⚠️ **AppContainer のアプリからは起動できない**(決定 0031)。メニューは出るが
`ShellExecuteEx` が拒否される。黙って何も起きないので、そこは
スタートメニューから開くことになる。
