# 決定 0037 — 個人化の学習材料をユーザーが明示的に渡せるようにする

決定 0034 の残件。決定 0016 / 0025 の同意境界に新しい分類を1つ足すので、
0034 の追記ではなく独立した決定にする。

## 何が問題だったか

個人化は**確定した語句だけ**を材料に個人 n-gram を学習する。その個人モデルは
**base から引き算される**(`alpha * (log p_personal - log p_base)`)。

材料の量が桁違いに違う:

| | 学習に使う文字数 |
|---|---|
| 出荷する base(Wikipedia) | **約 42万字** |
| 個人モデル(確定した語句、上限1万行) | **数千字** |

決定 0034 は「式の欠陥ではなく入力の欠陥ではないか」を疑い、
語彙を3.5倍にしても混合項の広がりが縮まないことを実測して**その見立ては外した**。
最終的に害は案3(base から `resumeFilePattern` で学習し直す)で消えたので、
**いま残っているのは害ではなく効き幅**である。個人化が動かせるのは
「1位と1文字目を共有する候補」だけで(決定 0034)、材料が数千字ではその中でも
証拠が足りない読みが多い。

azooKey の `Tuner` は同じ仕組みを**桁違いのテキスト**で動かしている。
ただしその材料は「画面学習」— アプリをまたいだテキストの自動収集で、
**決定 0016(完全オフライン・収集しない)と決定 0025(学習は同意の対象)の
どちらとも両立しない。**

## 決定

**設定アプリからテキストファイルを1つ取り込めるようにする。収集はしない。**

`%LOCALAPPDATA%\Ohagey\personal\imported.txt`(UTF-8、1行1文)。
訓練入力に、登録語・コーパスと並べて渡す。

## なぜ「打鍵の記録」ではないのか — 決定 0025 との関係

決定 0025 の同意は「**入力した内容から学習する**」ことに対するものである。
取り込んだ文章はそれに当たらない。**利用者がファイルを選んで渡した**もので、
決定 0036 のユーザー辞書と同じ性質を持つ。

したがってユーザー辞書と同じ扱いにする:

| | コーパス(`corpus.txt`) | **取り込んだ文章(`imported.txt`)** | ユーザー辞書 |
|---|---|---|---|
| 由来 | 打鍵の記録 | **明示的に渡したファイル** | 明示的な登録 |
| 上限 | 1万行、古い行から落ちる | **10万字、超えたら拒否** | 1万語 |
| 「学習データを消去」 | **消える** | **消えない** | 消えない |
| 学習オフのとき | 書かれない | **訓練入力には入る** | 訓練入力には入る |
| 専用の削除手段 | (消去ボタン) | **専用の削除ボタン** | 辞書画面 |

⚠️ **`personal/` の中にありながら消去の対象外**という点だけ、素直な実装だと
間違えやすい。`LearningData.IsPersonalArtefact` は**消すものを列挙する**方式なので、
ファイルを足しても黙って消える側に入らない。テストで固定してある。

**学習オフでも訓練入力に入る**のはユーザー辞書と同じ規則だが、
`personalizationMode` のガードにより個人化が無効なら結局何も適用されない。
つまり「オフの人に勝手に効く」ことはない。

## 上限は文字数で切る — 10万字

**行数ではなく文字数。** 学習コストは文字数に比例する(決定 0034 の実測):

| | |
|---|---|
| 時間 | **41µs / 字** |
| ピークメモリ | **780 bytes / 字** |
| モデルサイズ | 18.9 bytes / 字 |

行数で切ると、1行の本を貼られたときに何も守れない。

**10万字にした根拠:**

- **再学習1回あたり +約4秒。** base 9.4MB の 7.9秒に対して妥当な増分で、
  duty cycle(決定 0034、`trainingDutyCycle = 0.10`)が間隔を伸ばして吸収する
- **`trainNGram` の天井(約400万字 / 3.1GB)から2桁下。** カウントをメモリに持つので、
  そこは近づいてよい数字ではない
- 出荷 base の学習量(約42万字)の約4分の1。個人モデルに効くには十分な量

⚠️ **取り込みは1回ではなく毎回払う。** 訓練は毎回コーパス全体を読み直すので、
取り込んだ10万字は**確定のたびに**読まれる。設定アプリはこれを取り込む前に
秒数で表示する。

### 切り捨てではなく拒否する

上限を超えたファイルは**先頭10万字を取って成功と言う**ことをしない。
それは「文書の前半だけで学習して、全部取り込んだと伝える」ことであり、
利用者にはどこまでが効いているのか見る手段が無い。**拒否して文字数を示す。**

## 変更を engine が知る方法 — `stat`、既存の規則

`UserDictionaryStore.reloadIfChanged` と**同じ方式**にした。変換の前に
更新日時を1回見る。設定アプリが書きエンジンが読むという関係が辞書と完全に同じで、
別の仕組みを増やす理由が無い。

- 変換1回に対する `stat` 1回は無視できる(変換は 137ms)
- 通知の取りこぼしが原理的に無い
- 設定監視(`SettingsWatcher`)とは別の話なので、そちらに相乗りしない

**ファイルが消えたことも検知する。** 消えたのに残り続けると、「削除」がモデルから
文章を取り除かず、次のエンジン再起動まで学習に効き続けてしまう。

## 重み付けはしない

登録語は `registeredWordWeight = 40` で繰り返して訓練入力に入れる(決定 0036)。
取り込んだ文章は**そのまま1回**入れる。

登録語は「この語をこう変換しろ」という指示なので、打った習慣より重くてよい。
取り込んだ文章は**文体の材料**であって指示ではない。40回繰り返せば、
モデルはその文書を*覚える*ことになり、語彙を学ぶことにならない。

## 引き受ける帰結

- 🔴 **平文のファイルが増える。** 利用者が渡したものなので中身は既知だが、
  `%LOCALAPPDATA%` に残る。設定アプリに削除ボタンを置き、
  「外部に送信されない」と明記する(決定 0016)
- ✅ **害は測った。戻っていない**(`tsf/Ohagey/tools/build-and-run-imported.ps1`)。
  出荷構成(release ビルド、環境変数の上書きなし、base は
  `%ProgramFiles%\Ohagey\models\`、Zenzai 実稼働)で:

  | 取り込んだ量 | 学習時間 | 評価セットで1位が正解 | 壊れた |
  |---|---|---|---|
  | 1,074字(82行) | 10.1s | 30 → **30** / 32 | **0** |
  | **81,234字(3,117行、上限の81%)** | 13.0s | 30 → **30** / 32 | **0** |

  上限に近い量でも巻き添えは0件。**「材料を増やすと害が戻る」ことはない。**
  学習時間の差(10.1s → 13.0s)は 41µs/字 の見積り(80,160字 ≈ 3.3s)と一致する
- ⚠️ **効果(昇格)は未実測。** このハーネスは「壊さないこと」だけを主張する。
  昇格を示すには「学習ストアだけでは上がらない、かつ1位と1文字目を共有する」読みが
  要り(決定 0034)、それは `build-and-run-learning.ps1` の仕事である。
  決定 0034 は学習ストアの昇格を個人化の手柄と読む取り違えを3回しているので、
  **ここで両方を主張しない**
- 🔴 **ハーネスは最初の実行で嘘をついた。** `0 of 32` の状態で「broke 0 / ALL PASSED」と
  報告した — 正解が1件も無ければ壊すものも無いので、算術的には正しい。
  原因は変換そのものの失敗で、**エンジンの隣に `backends\cpu\` が無く Zenzai が
  無効だった**(エンジンは自分の実行ファイルからの相対でバックエンドを探す)。
  **ベースラインが半数を切ったら測定を拒否する**ようにした。
  決定 0034 が「緑だから信じた」を3回やっているので、緑の条件のほうを疑う
- **正規化が3か所に書かれた。** Swift(`PersonalizationLayout.importedLines`)、
  C#(`ImportedText.Normalise`)、そして両者を突き合わせるテスト。
  食い違うと「取り込んだと表示された文字数と、実際に学習される量が違う」という
  静かな壊れ方をするので、決定 0035 と同じ扱いでテストに固定した。
  ⚠️ **Swift の `Character.isNewline` は NEL(U+0085)と U+2028 / U+2029 も含む。**
  C# 側で `\r\n` だけを見ると行が繋がり、長さ上限で落ちて「文章が消えた」に見える
