# 0008: モデル配布方式

## 決定事項
Zenzaiモデル(`zenz-v3.1-small-gguf`)は、Inno Setupのインストーラーがインストール時に
Hugging Face(`https://huggingface.co/Miwa-Keita/zenz-v3.1-small-gguf`)から直接ダウンロード
します。インストーラー自体には同梱しません。

ダウンロードに失敗した場合(オフラインインストール、ネットワーク制限のある環境 — 学校PC・
管理されたPCでよくあるケース)でも、インストール自体は成功させます。おはぎーは、モデルが
用意できるまでAzooKeyKanaKanjiConverterの非ニューラル・辞書ベース変換(`zenzaiMode: .off`
相当)にフォールバックします。モデルは設定アプリからいつでも再取得を試せます。

## 理由
- 開発中に頻繁に再ビルド・再配布するインストーラーを軽量・高速に保てる
- 先行事例と一致する(`unok/myime`も同じHugging Faceリポジトリから`ggml-model-Q5_K_M.gguf`を
  インストール時にダウンロードし、失敗しても続行する設計)
- 「インストールはできたが一切入力できない」という最悪の失敗モードを避けられる

## 保存場所
`%ProgramFiles%\Ohagey\models\ggml-model-Q5_K_M.gguf`(マシン全体で共有、全ユーザー共通)。
モデル自体にはユーザー固有のデータは含まれないため、`%LOCALAPPDATA%`配下に置く学習データ
(決定0024を参照)とは異なる扱いにしています。

## 開発用のパス上書き `OHAGEY_MODEL_PATH`(2026-07 追記)

上記の保存場所は**書き込みに管理者権限が要る**。つまりこれだけだと、開発者は
昇格しない限り Zenzai 経路を一切テストできない。実際にフェーズ1でこれに突き当たった。

`ProgramFiles` 環境変数を差し替える回避策は**使えない**。Windows は新規プロセス生成時に
この変数をレジストリから再設定するため、子プロセスには元の値しか渡らない(実測で確認)。

そこで `OHAGEY_MODEL_PATH` を用意し、設定されていればそのパスを使う。

### ただし debug ビルドでのみ有効にする

**出荷ビルドでは無視する。** エンジンは最初に接続したクライアントが
オンデマンド起動する(決定 0015)ため、**起動元アプリケーションの環境変数を継承する**。
release で上書きを効かせると、セッション内の任意のアプリが「他の全アプリと共有される
エンジン」に読ませるモデルファイルを選べることになる。llama.cpp の gguf パーサに
攻撃者が選んだファイルを渡せる状態は作りたくない。

開発者は debug をビルドするので、debug 限定にしても失うものは無い。
判定は `EnginePaths.honorsModelPathOverride`(`#if DEBUG`)にあり、
ビルド構成で決まる — 実行時に切り替えられるフラグにはしていない。

**実機で確認済み**: debug は上書きに従い(不正なパスを指せばモデル無しと判定する)、
release は同じ環境変数があっても無視して `%ProgramFiles%` から読む。
`swift test` は debug / release **両構成**で通し、この分岐自体もテストしている。

## 追記(2026-08-04)— 取得するファイルが5件になり、ハッシュで固定した

決定 0034 の個人化には base 言語モデルが要ることが分かった(決定 0034 の 2026-08-04
追記)。**無いと個人化は「弱く効く」のではなく完全に無効になる。** インストーラが
取得するのは次の5件になった:

| ファイル | 元 | サイズ | ライセンス |
|---|---|---|---|
| `ggml-model-Q5_K_M.gguf` | `Miwa-Keita/zenz-v3.1-small-gguf` | 70.4MB | CC-BY-SA 4.0 |
| `lm_c_abc.marisa` | `Miwa-Keita/base_n5_lm` | 19.7MB | **記載なし**(決定 0009 の追記) |
| `lm_r_xbx.marisa` | 同上 | 3.4MB | 同上 |
| `lm_u_abx.marisa` | 同上 | 9.4MB | 同上 |
| `lm_u_xbc.marisa` | 同上 | 10.1MB | 同上 |

**取得失敗で中断しない方針は変えない。** 5件それぞれが独立に失敗しうる。zenz が
落ちれば辞書変換に、base LM が落ちれば個人化なしに、それぞれ縮退する。

### `installer/download-model.ps1`(新規)

これまで `[Run]` が呼んでいた `download-model.ps1` は**存在しなかった**。実装した。
1ファイル1呼び出しで、**必ず exit 0** を返し、経緯を `{app}\models\download.log`
に書く。

**中途半端なファイルを絶対に残さない。** エンジンは「ファイルがあるか」で Zenzai の
可否を決め、見つけたものをそのまま llama.cpp の gguf パーサに渡す。切れたダウンロードは
「見つかって、読まれて、弾かれる」— 良くてそれで、悪ければもっと悪い。
すべて `.partial` に落とし、全体が届いてハッシュが一致してから rename する。

**SHA-256 で固定した。** 経路(HTTPS)ではなく**出所**への対処である。取得元は
第三者の Hugging Face リポジトリで、いつでも更新されうる。うち1つはライセンスの
記載すら無い。固定してあれば、上流の変更は「ダウンロードが飛ばされた」として現れ、
「誰も動かしたことのないモデルを積んだユーザー」としては現れない。
ハッシュは 2026-08-04 に**上流と突き合わせて検証した**。

Windows PowerShell 5.1 向けに書いてある(Inno が起動するのは `pwsh` ではなく
`powershell.exe`)。そのため:

- **スクリプトは ASCII のみ**。5.1 は BOM 無し UTF-8 を ANSI として読むので、
  日本語 Windows では em ダッシュ1つでログが化ける(実際に化けた)
- TLS 1.2 を明示的に有効化する。無いと Hugging Face への要求が「ネットワーク障害」に
  見えるプロトコルエラーで落ちる
- `$ProgressPreference = "SilentlyContinue"`。5.1 の進捗バーは大きなダウンロードを
  数倍遅くする。しかも `runhidden` なので誰も見ていない
- `[Run]` の `Filename` は `powershell.exe`。`.ps1` を直に指すと Inno は拡張子に
  関連付けられたプログラム(既定の Windows ではメモ帳)に渡してしまう

### 検証済み(スタンドアロン)

- 既にあってハッシュ一致 → 何もしない
- 既にあってハッシュ不一致 + オフライン → **既存ファイルを消さない**
- 無くてオフライン → exit 0、`.partial` も残さない
- 5件すべてを実際に取得し、固定したハッシュと一致することを確認

インストーラ全体(`iscc`)はまだ通していない。`[Files]` が実ビルド成果物を待っている
ため、`[Run]` の行もコメントのままである。
